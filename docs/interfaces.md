| Interface | Contract | Source anchors |

| Decky Terminal Mode frontend to backend | `ping`, `get_cli_profiles`, `get_cli_profile_health`, `get_cli_setup_plan`, `open_cli_setup_action`, `get_agent_pack_install_plan`, `install_agent_pack`, `get_plugin_update_plan`, `update_plugin_to_latest`, `get_permission_bypass_plan`, `update_permission_bypass`, `get_release_channel`, `set_release_channel`, `add_cli_profile`, `remove_cli_profile`, `get_terminal_config`, `update_terminal_config`, `get_voice_transcription_config`, `update_voice_transcription_config`, `start_voice_capture`, `stop_voice_capture`, `cancel_voice_capture`, `transcribe_voice_audio`, `list_terminal_sessions`, `open_terminal_profile`, `start_terminal_session`, `read_terminal_session`, `get_terminal_session_links`, `clear_terminal_session_links`, `write_terminal_session`, `resize_terminal_session`, `interrupt_terminal_session`, `restart_terminal_session`, `stop_terminal_session`, `stop_all_terminal_sessions`, and `get_storage_plan` Python calls for on-Deck smoke/MVP testing. `get_terminal_config` and `update_terminal_config` persist terminal display/input/voice settings, including `dpad_mode` (`arrows` or `scroll`), `auto_copy_selection`, `voice_input`, and `voice_prefer_native_cli`; legacy `use_dpad` remains accepted for existing settings payloads and a stored legacy `navigation` DPad mode is normalized to `arrows`. Terminal input capture is always enabled in terminal routes and is not user-configurable. Terminal mode renders toolbar, auth-link, paste fallback, voice, and extra-key controls without placing those buttons in Decky controller focus; controller focus stays on xterm, while a top help button opens a column of terminal shortcuts instead of using Steam's expanded action footer. The xterm host is not a nested Decky focus target, so controller capture stays on the terminal page instead of alternating between terminal and route focus. Toolbar Paste, the Y shortcut, and intercepted Ctrl+V / Cmd+V / Shift+Insert all route through one paste flow that reads the clipboard through the backend, which reads the gamescope Xwayland selection directly via libX11 (`DISPLAY` :0/:1, `CLIPBOARD` then `PRIMARY`) — the focus-independent path that works in Gaming Mode; there are no wl-paste/xclip/xsel/klipper, native Steam `Browser.Paste`, in-process mirror, or manual paste-panel fallbacks, a raw Ctrl+V never reaches the CLI, clipboard text is always written to the PTY as plain (bracketed) text, and Copy writes the selection back to the same Xwayland clipboard via `execCommand("copy")`. The voice toolbar button is the only external dictation control: first press starts recording, second press stops recording/transcribes, and recognized text is always inserted automatically without pressing Enter. `get_voice_transcription_config` and `update_voice_transcription_config` persist an opt-in OpenAI-compatible transcription endpoint URL, model, and API key. The public config returns only `api_key_required` and `api_key_configured`; it never returns the key. `start_voice_capture` starts one user-requested backend microphone capture with a supported local recorder and returns a structured `error` field on failure so Decky does not collapse the reason into a generic callable error. `stop_voice_capture` finalizes a WAV clip, validates that captured audio has frames, enforces the 8 MiB audio limit, POSTs multipart form-data with `file`, `model`, and `response_format=json` to the configured endpoint over verified TLS for HTTPS URLs, returns capture metadata on success, and returns a sanitized structured `error` field on capture or API failure. HTTPS transcription uses explicit system CA bundle discovery when the Decky runtime does not expose Python's default CA paths. `cancel_voice_capture` stops and deletes any in-flight clip. `transcribe_voice_audio` remains a bounded direct base64 transcription callable for compatibility. `get_agent_pack_install_plan` reports user-local write paths for Codex and Claude native assets; `install_agent_pack` requires explicit confirmation and refuses unsupported or missing-source targets. `get_plugin_update_plan` checks GitHub Releases for the latest compatible plugin ZIP and reports `low_write` update status. The frontend `Update plugin` action first calls Decky Loader's `utilities/install_plugin` with the GitHub Release ZIP, the release version, the SHA-256 digest when GitHub provides it, and Decky `InstallType.UPDATE`, so root-owned plugin directories are replaced by Decky Loader rather than by the plugin backend. `update_plugin_to_latest` remains a backend fallback for runtimes without the Decky install API; it requires explicit confirmation, validates the downloaded release ZIP structure, verifies the install target is writable before replacing bundled plugin files, logs update failures, and expects Decky plugin reload afterward. `get_release_channel` and `set_release_channel` persist the opt-in release channel in `release-channel.json` (default `stable`); the update plan and installer filter GitHub Releases by it — a `stable` channel ignores pre-releases while a `dev` channel also receives them — and every update plan payload carries the active `channel`. `get_permission_bypass_plan` returns the current per-profile bypass plan and `update_permission_bypass` persists the owner-controlled toggle in Decky settings. Enabled built-in profiles launch with CLI-native no-approval args: Codex `--dangerously-bypass-approvals-and-sandbox` and Claude `--permission-mode bypassPermissions`; custom profiles are trusted as configured without argv rewriting. `read_terminal_session` records HTTP(S) links and a bounded in-memory output tail from PTY output; `get_terminal_session_links` returns recent non-suppressed links plus that output tail so the terminal page can expose Open/Copy/Hide actions and replay the last visible terminal text after route remounts. `clear_terminal_session_links` suppresses stale helper links without deleting terminal replay. `open_terminal_profile` and `open_cli_setup_action` reuse a running matching PTY or start it if none is alive. Terminal sessions persist until the user closes them or the plugin unloads. | [main.py](../main.py), [src/index.tsx](../src/index.tsx), [docs/operations.md](operations.md) |
| Optional local streaming transport | Planned terminal stream transport if Decky method calls are insufficient for PTY throughput | [ROADMAP.md](../ROADMAP.md) |
| Optional hosted pack registry | Static JSON registry with pack metadata and artifact URLs | [ROADMAP.md](../ROADMAP.md) |

## Compatibility Notes

- Codex and Claude are the supported target-native assistant pack hosts.
- OpenCode should be treated as reference material for primary-agent/subagent separation, not as an MVP provider target.
- Hermes and OpenClaw are reference architectures, not MVP dependencies.
- Every target CLI adapter must degrade to plain Terminal Mode if native plugin/skill integration is unavailable.
- Terminal voice controls must degrade to plain typed/pasted Terminal Mode when external API recording/transcription or an explicitly selected CLI-native voice path is unavailable.
- Claude Code native voice support was checked against official docs on 2026-06-23: `/voice` is available in Claude Code v2.1.69 or later, with `/voice tap` requiring v2.1.116 or later; transcription is owned by Claude Code, not this plugin, and remains opt-in. Codex CLI has no documented stable native voice command in the official Codex CLI docs checked the same day, so Codex uses the configured external transcription path when available.
- MCP config shapes for Claude Code were verified against official docs on 2026-06-21; Codex MCP and plugin metadata paths were rechecked against official OpenAI Codex docs on 2026-06-23. Bundled native adapter installation is implemented as user-local file installation, while public marketplace/release distribution remains separate release work.
